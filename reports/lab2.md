## 编程作业

`mmap` 用于将一个文件或者其他对象映射到进程的地址空间中。这样，文件的内容就可以像访问内存一样被访问，这通常比传统的 read 和 write 系统调用更加高效。`mmap` 也可以用于映射匿名内存，即不与任何文件关联的内存区域，这通常用于进程间共享内存。`munmap` 用于撤销由 `mmap` 创建的内存映射。当一个内存区域不再需要映射时，使用 `munmap` 可以释放该区域，让操作系统回收这部分资源。这对于管理内存资源和避免内存泄漏非常重要。总结来说，`mmap` 用于创建内存映射，而 `munmap` 用于撤销这些映射，它们是进行高效文件操作和内存管理的重要工具。



## 简答作业

1. 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？

在 ARMv7 和 ARMv8（也就是 AArch32 和 AArch64）架构中，SV39（Stage 1 and Stage 2 Translation with 3-level page tables）是一种分页机制，它使用三级页表来实现虚拟地址到物理地址的转换。在 AArch64 架构中，页表项（PTE）的组成如下：

1. **物理地址**：页表项的大部分位用于存储物理页帧的地址。在 4KB 页的情况下，这是 36 位（48 位地址空间中的高 36 位），因为物理地址的低 12 位始终为零（因为页帧大小是 4KB）。
2. **有效位（Valid）**：如果设置，表示该页表项是有效的，转换完成。
3. **页表属性索引（Table Attributes Index, TAI）**：用于选择一组非内存属性（如缓存和共享属性）。
4. **全局标志（Global flag, G）**：如果设置，表示映射的页是全局的，对所有地址空间都可见。否则，它可能被任何地址空间的转换操作替换。
5. **内存属性索引（Memory Attribute Index, MT）**：用于选择内存属性，如内联缓存策略。
6. **共享属性（Shareability attribute, SH）**：定义了页的共享级别，比如是否是设备内存。
7. **访问权限位**：
   - **AP[1:0]**：访问权限位，控制对页的读写权限。
   - **APTable[1:0]**：用于页表项的访问权限。
8. **非全局标志（nG）**：如果设置，表示该页表项是局部的，仅对创建它的地址空间可见。
9. **脏位（Dirty bit, D）**：如果设置，表示页被写入过。
10. **4KB 页只读位（PXN）**：如果设置，表示该页是不可执行的。
11. **4KB 页特权执行从不位（PAN）**：如果设置，表示该页在用户模式下是可访问的。
12. **16KB 或 64KB 页的访问权限位扩展（AP[2])**：对于更大的页，提供额外的访问权限控制。
13. **16KB 或 64KB 页的非全局标志（nG）**：对于更大的页，提供非全局标志。

这些标志位的作用主要是控制页表项的行为，包括访问权限、内存属性、页的共享和缓存行为等。通过这些标志位，操作系统可以灵活地管理内存，确保安全性和效率。例如，通过设置脏位，操作系统可以跟踪哪些页被修改过，从而在必要时将它们写回磁盘。通过访问权限位，可以控制哪些进程可以访问或修改特定的内存区域。



2. 缺页

   缺页指的是进程访问页面时页面不在页表中或在页表中无效的现象，此时 MMU 将会返回一个中断， 告知 os 进程内存访问出了问题。os 选择填补页表并重新执行异常指令或者杀死进程。

   - 请问哪些异常可能是缺页导致的？
     - **保护异常（Protection Fault）**：尝试访问没有权限的内存页面。
     - **无效访问异常（Invalid Access Fault）**：尝试访问一个无效的内存地址，比如未映射的地址。
     - **硬件异常（Hardware Fault）**：某些硬件错误也可能导致缺页异常，比如内存访问越界。
   - 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。
     - **程序计数器（Program Counter, PC）**：保存导致缺页的指令的地址。
     - **链接寄存器（Link Register, LR）**：在某些架构中，保存返回地址，特别是在分支指令后。
     - **状态寄存器（Status Register）**：保存当前处理器的状态，包括特权级别和中断使能状态。
     - **内存管理寄存器**：如页表基址寄存器（Page Table Base Register），可能包含当前页表的基地址。

   缺页有两个常见的原因，其一是 Lazy 策略，也就是直到内存页面被访问才实际进行页表操作。 比如，一个程序被执行时，进程的代码段理论上需要从磁盘加载到内存。但是 os 并不会马上这样做， 而是会保存 .text 段在磁盘的位置信息，在这些代码第一次被执行时才完成从磁盘的加载操作。

   - 这样做有哪些好处？
     - **减少启动时间**：程序启动时不需要加载全部代码到内存，可以快速启动。
     - **节省内存**：只有实际需要的代码和数据才会被加载到内存，减少内存使用。
     - **提高效率**：只有实际访问的页面才会被加载，避免了不必要的磁盘I/O操作。

   其实，我们的 mmap 也可以采取 Lazy 策略，比如：一个用户进程先后申请了 10G 的内存空间， 然后用了其中 1M 就直接退出了。按照现在的做法，我们显然亏大了，进行了很多没有意义的页表操作。

   - 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？

     - **页大小**：4KB
     - **一级页表项数量**：10G / 4KB = 2,625,000个页表项
     - **每个页表项大小**：8字节
     - **一级页表大小**：2,625,000×8B=20,000,000B 或 20MB

     由于SV39是三级页表，每个一级页表项指向一个二级页表，每个二级页表项指向一个三级页表。因此，每个级别的页表大小大致相同，总共需要三级，所以总的页表大小大约是 20MB×3=60MB20*MB*×3=60*MB*。这是一个粗略估计，实际大小可能会因页表的填充率和具体实现而异。

   - 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。

     - **页表项设置**：在页表项中设置适当的标志位，表示页面尚未加载到物理内存中。
     - **缺页处理**：当访问未加载的页面时，触发缺页中断。操作系统捕获中断，从磁盘加载所需的页面到物理内存中。
     - **更新页表**：加载页面后，更新页表项，设置有效标志位，并可能更新其他属性，如脏位。
     - **重新执行指令**：缺页处理完成后，重新执行导致缺页的指令。

   缺页的另一个常见原因是 swap 策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效。

   - 此时页面失效如何表现在页表项(PTE)上？

     - 在 swap 策略中，页面可能被换出到磁盘，这在页表项中通常表现为：

       - **有效位**：清除有效位，表示页面当前不在物理内存中。
       - **存在位**：在某些系统中，存在位（Present bit）会被清除，表示页面不在内存中。
       - **修改位**：如果页面被修改过，脏位会被设置，以确保换入时能够正确处理。

       当页面被换入时，这些位会被重新设置，以反映页面现在的状态。

       

3. 双页表与单页表

   为了防范侧信道攻击，我们的 os 使用了双页表。但是传统的设计一直是单页表的，也就是说， 用户线程和对应的内核线程共用同一张页表，只不过内核对应的地址只允许在内核态访问。 (备注：这里的单/双的说法仅为自创的通俗说法，并无这个名词概念，详情见 [KPTI](https://en.wikipedia.org/wiki/Kernel_page-table_isolation) )

   - 在单页表情况下，如何更换页表？

     - 在单页表的情况下，更换页表通常涉及到修改控制寄存器中的页表基址（例如，在x86架构中是CR3寄存器，在ARM架构中是TTBR寄存器）。这个寄存器指向当前正在使用的页表的起始地址。更换页表通常涉及以下步骤：
       1. **准备新的页表**：创建或更新一个新的页表，确保它包含了所有必要的映射。
       2. **更新页表基址寄存器**：将页表基址寄存器更新为新页表的物理地址。
       3. **确保一致性**：在更新寄存器之前，确保所有的CPU缓存都被清空，以确保新的页表能够立即生效。

   - 单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）

     - 在单页表情况下，控制用户态无法访问内核页面通常通过以下方式实现：
       - **访问权限控制**：在页表项中设置访问权限，使得内核页面只对内核态可访问。例如，在x86架构中，可以通过设置页表项的USER/SUPERVISOR位来控制。
       - **地址空间布局**：将内核空间和用户空间映射到不同的地址范围，确保用户空间的地址无法映射到内核空间。
       - **内存管理单元（MMU）**：利用MMU的保护机制，确保在用户态执行时，任何尝试访问内核空间的尝试都会触发保护异常。

   - 单页表有何优势？（回答合理即可）

     - 单页表的优势包括：
       1. **简化设计**：不需要维护两套页表，简化了操作系统的设计和实现。
       2. **减少内存占用**：只需要存储一套页表，减少了内存的使用。
       3. **提高效率**：在上下文切换时，不需要频繁地更换页表，减少了页表切换的开销。

   - 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？

     - **上下文切换**：在用户线程和内核线程之间切换时，需要更换页表以确保正确的地址映射。

     - **安全上下文变化**：在从用户态切换到内核态时，需要更换页表以防止用户态代码访问内核地址空间。

     - **加载新的执行环境**：在加载新的程序或模块时，可能需要更换页表以加载新的地址映射。

     - 如果设计一个单页表操作系统，更换页表的时机可能包括：

       1. **进程切换**：在进程上下文切换时，更换页表以确保每个进程有自己的地址空间。
       2. **特权级变化**：在用户态和内核态之间切换时，通过修改页表项的权限来控制访问，而不是更换整个页表。
       3. **内存保护**：在需要保护某些内存区域不被特定进程访问时，动态更新页表项的权限。
       4. **加载模块或动态链接库**：在加载新的模块或库时，更新页表以包含新的地址映射。

       通过这种方式，可以在保持单页表设计的同时，提供必要的内存管理和保护机制。
